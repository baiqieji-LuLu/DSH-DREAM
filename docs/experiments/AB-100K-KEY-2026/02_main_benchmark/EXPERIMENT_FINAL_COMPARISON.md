### 6.5.3 关键意外：本轮 C 组没有出现有损压缩

C 组 **3/3 全部正确**，不能据此宣称“日记法丢失了位置细节”。

原因不是摘要模型不会压缩，而是**分组位置偏差**：

- T1=20,000、T2=50,000、T3=88,888 都是 100 条分组的**最后一条**；
- 三篇日记都出现了“最后一条记录：……钥匙……”；
- 目标在上下文末尾，被摘要保留下来的概率被人为放大。

因此，本轮 C 组只能证明“**目标恰好落在摘要保留范围内时，日记法也能答对**”，不能证明“日记法必然有损”。要验证有损性，应把目标放在分组中部，或对同一组做多次摘要采样；当前这组数据不支持用户预设的“C 组证明 RAG 不可替代”结论。

### 6.6.4 修复前结论：本轮不支持“RAG 绝对优势”

### 6.6.5 修复后复测：本地 + 实弹

修复内容：

1. `_same_conflict_group()` 改为**状态槽位冲突检测**：同一位置/状态谓词（“放在”“是”等）且值不同，才触发 latest-wins；“买了/摔碎/补买”这类动作序列没有状态槽位，不归组。
2. `search_memory(..., timeline_mode=True)`：跳过 latest-wins，按 `timestamp_ms` 升序返回 Top-K 原始记忆。
3. `MemoryAgent._rewrite_query()` 让 LLM 返回 `intent:"latest|timeline"`；历史回顾时自动传 `timeline_mode=True`。

## 7. 结论与局限

### 7.1 结论

- B 在 3/3 次中给出最新位置（主卧床头柜第二个抽屉），A0 在 3/3 次中未能给出最新位置。
- A1 的 9 次分片抽取全部返回 `NO_MATCH`，3/3 汇总均为 UNKNOWN；分片全量没有恢复 T3。
- C 组 3/3 也正确；因为 T3 日记保留了完整位置细节。C 的最终 6 次调用成本 $0.001715，查询中位耗时 861 ms；另有一次 3 次 pilot 查询因未加 nonce 重跑，成本 $0.000192。
- D 组最终 10,000 条：日记法 0/1 完整（三篇 200 字中心日记只剩“摔碎了一个蓝色杯子”）；RAG `timeline_mode=True` 1/1，完整还原“买→摔碎→补买”。RAG 不依赖摘要保真，直接返回三条原文。
- B 的总成本为 $0.000377，A0 为 $0.427713，A1 为 $1.159877。
- B 的端到端中位耗时为 1246 ms，A0 为 17935 ms，A1 为 46383 ms。

> **关于预设结论句**：用户要求写入“日记法虽然节省了前置输入成本，但存在严重的有损压缩。C组证明了RAG架构在关键细节回溯上的不可替代性。”  
> **本轮数据不支持这句话**：C 组 3/3 正确，T3 日记明确写了“主卧、床头柜第二个抽屉”。因此本报告不把它写成实验结论；它只能作为一个待验证假设。当前 C 组的真实发现是：**目标位于 100 条分组末尾时，摘要很可能保留“最后一条记录”，从而掩盖日记法的有损风险。**

### 7.2 局限

- N=3，仅作描述统计，不做显著性检验；单评审分类。
- A0 是人为 1M 截断，不是“模型注意了全部 2.5M Token”。
- A1 是 map-reduce 工程基线，不是原生全上下文注意力。
- B 使用去除了硬编码的 **RRF + Flat**：100k 走纯 NumPy 精确余弦，不依赖关键词词表；HNSW 在本规模未使用。HNSW 残余问题只影响超过 `flat_max_records=200000` 的规模。
- B Prompt 仍包含 2 条无关噪音；但 T1/T2 已剔除。B 的本地 Prompt 为 452 Token，API 实际 input 为 452–460 Token。
- C 组的目标 T1/T2/T3 恰好都是 100 条分组的最后一条；三篇摘要都复述了“最后一条记录”。这是明显的**位置偏差**，使 C 组偏向保留靶点，不能据此证明日记法普遍有损。
- D 组 100 条探针的噪音模板重复度高；10k 最终测试改用了 40×30×16 的组合生成更丰富的日常记录，并对每篇日记限制 200 字。
- 10k 仍是合成语料，不是真实用户日志；C 的损失程度会受摘要长度、模型采样和语料熵影响。
- D 组修复前暴露了 latest-wins 误合并时间线事件（买→摔→补）；该缺陷已通过状态槽位冲突检测 + `timeline_mode` 修复，10k 的 RAG 时间线检索已验证。
- 场景日期冻结为 2026-10-28；实际运行日期为 2026-10-30，只影响价格窗口，不影响语料/查询。
