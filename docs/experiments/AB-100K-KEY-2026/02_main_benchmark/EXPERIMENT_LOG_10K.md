## 0. 先看这里：可能影响结论的设计选择

这部分是审计重点，不藏在附录里。

### 0.1 靶点位置与分组边界

要求的目标位置是第 **2,500 / 5,000 / 7,500** 条。

如果严格按“每 100 条一组”，这三个位置恰好是第 25 / 50 / 75 组的**最后一条**，又会回到上一轮的位置偏差。

因此本次同时保留两套日记：

| 类型 | 分组方式 | 靶点位置 |
|---|---|---|
| 100 篇标准日记 | 1–100、101–200、…… | 靶点在第 25/50/75 组末尾 |
| 3 篇中心日记 | 2451–2550、4951–5050、7451–7550 | 靶点在第 50 条（正中） |

**C-10k 查询使用的是 3 篇中心日记**，不是标准日记。标准日记仍全部生成并保留，用于对照。  
这不是“只挑对结论有利的日记”：标准日记中匹配到的组是 **50、75**（第 25 篇标准日记完全没提杯子），同样无法还原购买事实。两套都不完整，只是中心日记更符合“靶点居中”的要求。

### 0.2 两次 10k 运行，第一次被废弃但计费

| 运行 | 结果 | 处理 |
|---|---|---|
| `trivia-10k-20261031T005206` | 100 标准 + 3 中心 + C 查询；无 200 字限制 | **废弃，不作最终证据**；104 次调用成本仍计入总账 |
| `trivia-10k-v2-20261031T005556` | 100 标准 + 3 中心 + C/RAG 查询；200 字限制 | **最终数据**；105 次调用 |

第一次日记没有长度限制，模型把 100 条记录几乎逐条复述，C 仍然答对；这不能证明“日记法没有损失”，只能证明**长摘要没有压缩**。因此第二次把日记限制为 200 字，才是真正的有损压缩测试。

**这一点必须披露**：200 字是实验者设定的摘要预算；如果不限制长度，C 可能保留更多细节。最终结论只适用于“200 字日记”这一条件。

## 8. 结论与不确定性

### 结论

在 10,000 条语料、靶点居中、日记限制 200 字的条件下：

- **C-10k 有损**：三篇日记只剩“摔碎了一个蓝色马克杯”；
- **B-10k 无损**：RAG 时间线完整还原“买→摔碎→补买”。

### 不确定性

- 10k 是合成语料，不是真实用户日志；
- 200 字是人为设定的日记预算，换更长的摘要可能保留更多细节；
- C 查询只用了 3 篇中心日记；标准日记的对照结果也保留，但标准日记的分组同样把靶点放在末尾；
- N=1 次 C 查询、1 次 RAG 查询；不是多次采样统计；
- RAG Top-5 含 2 条噪音，但 3 条靶点全命中，时间线顺序正确。

**审计判断**：本轮结果不是通过修改代码、硬编码 ID 或挑选回答得到的；最大的可争议点是“200 字摘要预算”和“中心窗口”这两个设计选择，二者已明确披露。
